Slice Y (rung 65, the lagged bleed valve) opened phase 6's last deferred hook cell and changed one
gated signature. Two process lessons, both about instruments rather than code.

**A DESIGN RETIRED FIELD-BY-FIELD IS NOT A DEAD DESIGN — EMIT THE SET BEFORE BURYING IT.** The
plan's uniform `Scope` parameter had been refused twice (slices V and X) on the strength of a body
read each time, and looked finished. Emitting *every* `_stator_march` signature in the ladder
showed rungs 65/66/67/68 each add one per-march parameter to the SAME cell in the SAME
save-previous/restore shape — five parameters, one cell. Opened once as a struct, that is one
non-additive change instead of four. Two local refusals had been read as a global verdict.

**A `-x` CENSUS ON THIS REPO REPORTS THE DURATION CACHE, NOT THE CODE.** `conftest.py` orders
collection longest-first from a learned-duration cache that every run rewrites, so with
stop-at-first-failure the "first failing test / N passed" column is not reproducible: three runs of
one injection gave three different answers. The caught/ungated verdict survived all three. Drop
`-x` and report the SET of failing gates — order-independent, and strictly more informative.
Slice X's census carries the same defect; its verdicts stand, its detail column does not.

**Why:** both failures are the same shape — a conclusion drawn from an instrument nobody asked to
prove itself. See [[rust-port-guessed-census-bars]] and [[rust-port-slice-w-step3]].

**How to apply:** before declaring an architectural decision closed, emit the whole set it ranges
over. Before reporting a census column, run the census twice and check the column is the same.
