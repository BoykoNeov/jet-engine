**THE LESSON — a booking no gate can close is not a gate nobody wrote, it is a claim in the
WRONG CURRENCY.** Slice AC booked a same-field nest of the two frozen-state fields to this
slice and could not close it, because the thing at stake — whether the port's guard restores
`None` (Python's choice) or the PREVIOUS value (Rust's natural one) — produces **identical
numbers on identical inputs at every reachable site**. No value gate can state it. The
discharge owed is therefore a STRUCTURAL claim verified per call site, plus a gate on the
weaker thing that IS testable (*the choice moves no key*). Writing a gate anyway would be
[[instrument-fed-by-what-it-certifies]] from the opposite side.

**THE SECOND LESSON — four instruments in a row returned a confident WRONG NUMBER, and three
were caught only by a hand reading of the site.**

* The static nest census was wrong in BOTH directions at once (called a nest not-nested and a
  non-nest nested), from one broken recursion.
* The runtime probe's first run read **0 sets, 0 nests** — a blind instrument, not a zero:
  `pytest.ini` injects `-n auto`, so the tests ran in eight workers while the controller wrote
  the shared tally last and clobbered theirs. Now `-n0`, one file per PID, and a **positive
  control before any test**.
* Its first working version capped the frame list at twelve, and all twelve were the same
  site — a one-bit reading of a four-valued question, which is [[rust-port-slice-ag-step7]]'s
  counting-pointer lesson recurring one slice later in another language.
* A `sum()` classifier was wrong twice about the SAME site, the second time for a new reason.

**How to apply:** a structural probe whose verdicts have not been checked against a hand
reading of at least one POSITIVE and one NEGATIVE site is unvalidated. At small n the
enumeration IS the measurement — read the sites.
