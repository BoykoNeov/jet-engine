#### (d) THE FINDING — **A FILE NAME IS NOT AN ENTRY CONTROL**

The first oracle was written by `cmd //c start //belownormal //b //wait "…\.venv\Scripts\python.exe"
"probe.py" out_pypy.tsv` from Git Bash. `start` takes its first QUOTED argument as the WINDOW
TITLE, so the interpreter path was eaten and `probe.py` ran through the `.py` file association —
**system CPython 3.14**. Nothing checked. The Rust gates then failed on 27 lines at two readings:
24 `summands` values in `scan_p4`'s ladder points 4 and 5, and `secant_iter_v4`'s second trace
`F`, `g` and `final_g` — the latter about 9 000 ulp apart.

The next hour went into root-causing that "divergence" against the wrong interpreter: a hand-built
trajectory dump, then an in-march capture of the Illinois closure in
`ScheduledBleedTransient._close_fuel` (`return ev(_illinois(g, lo, hi, glo, ghi, tol=1e-12))`),
then down to `ComponentMap.eta_c_at`'s `(n - 1.0) ** 2`, one ulp off on CPython (its `pow`
misrounds where PyPy's `x ** 2` is `x * x` — the port's recorded power-spelling split). A one-ulp
efficiency difference moves the Illinois root by up to the solver's `1e-12`, and the march
amplifies that. (One
detour inside that hour was itself wrong: `ev` evaluated after the march, when the armed state had
moved on, was corrected to an in-march capture.) Every step of it was accurate about CPython, and
irrelevant to the port.

port.
